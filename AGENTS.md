# Уроки отладки (из эпопеи с каруселью)

- **Сначала проверяй сами ассеты, а не код.** Если визуальный эффект «не работает» на картинке — открой сам файл. У `public/templates/*/preview.webp` вбитые прозрачные скруглённые углы (альфа-канал ~16px): ни один CSS-радиус больше этого не отобразится, пока картинку не зазуммить (`scale(1.15)` на img выносит вбитый край за границы слайда).
- **Верь пользователю, а не computed styles.** Если пользователь видит баг, а тесты «в изоляции работают» — проблема в окружении/данных, а не в его глазах. Не доказывай корректность кода, воспроизводи баг end-to-end.
- **Скриншот — истина.** Для UI-багов проверяй глазами: headless Chrome (`--screenshot`, при надобности CDP для computed styles/замеров). Одна картинка заменяет десять гипотез.
- **Самописная бесконечная карусель = сначала симуляция.** Любая логика рециркуляции/спейсинга проверяется численной симуляцией (200k кадров: позиции ограничены, дрейфа нет) до внедрения. Общая перспектива (vanishing point в центре экрана) взрывает ширину дальних карточек — использовать точную проекцию с клампом ширины (×1.15 к наивной).
- **Откатывай неудачные гипотезы сразу.** Не наслаивать фиксы друг на друга: не сработало — вернуть как было и пробовать следующее.
- **Токены — на воспроизведение, не на теоретизирование.** Последовательность: воспроизвести → локализовать (бисекция, по одной переменной) → фикс → контрольный скрин. Не наоборот.

## Как читать скриншоты

- **Не судить детали по даунсэмплированному полному скрину.** Углы, радиусы, тонкие линии — только кропом в нативном разрешении (`region` в исходных пикселях файла, не в координатах показанной копии).
- **Сначала координаты элемента, потом кроп.** Не угадывать позицию угла «на глаз» — взять `getBoundingClientRect` (CDP/DevTools) и кропать по точным числам. Половина моих «багов» была кропом мимо угла.
- **Малое значение нечитаемо — проверять большим.** Радиус 20px на пёстрой картинке почти не виден; для проверки механизма временно ставить 80px. «Не вижу» ≠ «не работает».
- **Отличать клип элемента от рамки контента.** У картинки могут быть свои вбитые поля/альфа-угол: проверять контрастной подложкой (яркий фон под элемент) или чтением пикселей (`getImageData` на canvas), а не глазомером.
- **Смотреть шире искомой точки.** Соседние элементы могут перекрывать искомое (оверлап прячет углы/края) — кроп всегда с запасом контекста.
- **Анимацию не судить по одному кадру.** Снимать несколько позиций/моментов; движущийся элемент на стоп-кадре может стоять в нетипичном месте.

# Экономика проверок (не жечь время и токены)

- **Иерархия проверок: дешёвое → дорогое.** Сначала код, grep, node-скрипт, curl (коды ответов, валидность JSON), потом DOM/computed styles, и только последним — скриншот. Скриншот — доказательство, а не способ думать.
- **Без браузера, если можно без браузера.** Валидность данных, 200/404, SEO-мета, состав JSON — проверяются curl/node. Playwright — только когда нужен рендер или интеракция.
- **Измеримое в DOM — не фотографируется.** Позиция (`getBoundingClientRect`), видимость, `opacity`/`transform`, наличие класса, состояние анимации (`currentFrame`, `isPaused`) — это один `evaluate`, а не серия картинок. Пример антипаттерна: три серии замеров хеша кадров вместо одного чтения `currentFrame`.
- **Скриншоты: один кроп вместо серии полных кадров.** Полный viewport — только когда важен контекст; детали — кропом по координатам элемента. Контрольный скрин после фикса — один, не «на всякий случай ещё пару».
- **Не перепроверять доказанное.** Если факт установлен (файл отдаётся, функция отработала в тесте), не гонять ту же проверку в других формах. Одна баг = одно воспроизведение + один контроль.
- **Батчить.** Несколько независимых проверок — в один `evaluate`/`Bash` с массивом результатов, а не по вызову на каждую.
- **Один инструмент на задачу.** Путь к файлу известен — `Read`, а не `ls`+`cat`; массовая замена — скрипт, а не ручные правки в цикле; поиск — `Grep`, а не чтение файлов подряд.

# Правила работы

- **Явные баги, найденные в процессе разработки — фиксить сразу**, даже если их не репортили. Не ограничиваться сообщением пользователю.
- **В финальный отчёт всегда включать репорт по багам:** какие баги были найдены и что конкретно сделано с каждым (фикс + где, либо почему отложен).

# Проектные решения (не откатывать без причины)

- **Sitemap — только MetadataRoute** (`app/sitemap.ts`): генерится на лету из `public/templates/index.json`, кеш 1ч (`revalidate = 3600`). НЕ возвращаться к генерации файла в public/ или к cron-роутам — это сознательный выбор (актуальность без обслуживания).
- **robots**: статичный `public/robots.txt`, одна секция `User-agent: *` (НЕ делить на GoogleBot/Yandex — при именной секции бот игнорирует `*`, из-за этого /cart и /checkout проходили для Google). Закрыты: /api/, /cart, /checkout, /favorites, /search, /my-account и ЛЮБЫЕ URL с GET-параметрами (`Disallow: /*?` — в индексе только чистые URL). Не возвращать app/robots.ts (конфликт со статикой).
- **Индексация мета**: сайт ПОКА закрыт — `robots: { index: false, follow: false }` в app/layout.tsx это осознанное решение, НЕ удалять до запуска. При открытии: снять noindex + всё остальное уже готово (`metadataBase: https://evspc.com` в layout; canonical на чистый URL в app/template/[slug] и app/category/[slug] — склеивает ?edit=/?sort=, закрытые в robots).
- **Шрифты редактора** — набор evyt в `public/fonts/` + `lib/editor-fonts.ts`, подключаются лениво через `injectFonts` (dedupe по family, НЕ перезаписывать style целиком — была гонка).
- **Фон шаблона** всегда залочен: fabric не сериализует selectable/evented → `lockTemplateBackgrounds` после каждого loadFromJSON (по src из template.json).
- **PNG заказов** хранится в `order_items.png_data` (рендер на клиенте при checkout), превью в `preview_url` (обе MEDIUMTEXT/LONGTEXT). Вебхук шлёт письмо с вложениями при `payment.succeeded`.
- **Тач-события fabric**: штатный `_onTouchStart` безусловно preventDefault (глушит скролл страницы) — пересажен на версию с preventDefault только на интерактивных объектах (useFabric); dblclick на тачах не существует — выделение слова через свой детектор даблтапа на `mouse:down`.
- **Цели Яндекс.Метрики** (счётчик 110908888 в Footer, lazyOnload): отправка только через `reachGoal()` из `lib/metrika.ts` — он создаёт стаб-очередь `ym.a`, т.к. tag.js грузится лениво и ранние события (mount на /cart, /checkout/success) иначе теряются. НЕ заменять на наивный `if (window.ym)`. Цели: add_cart (Editor + SavedDesigns), redirect_to_cart (/cart mount), push_pay (checkout submit), success_pay (ClearCartOnSuccess).
- **Оптимизатор next/image ВКЛЮЧЁН** (убран `unoptimized: true` из next.config.ts, коммит 173fcea «Remove image optimization» откачен): Lighthouse показывал ~1.6 МБ лишнего веса — превью 557×792 отдавались в контейнеры 180×256/285×405. Требования на проде: sharp под linux (`npm ci` без `--no-optional`), nginx должен проксировать `/_next/image` в Next (порт 4047) и передавать `Accept`. Проверка после деплоя: `curl -I "https://evspc.com/_next/image?url=%2Ftemplates%2F<slug>%2Fpreview.webp&w=384&q=75"` → 200 image/webp. `sizes` у fill-картинок уже прописаны везде (TemplateCard/AgeSection/FavoritesList/CategoryBrowser/PurchasedTemplates), у фиксированных (hero-декор, лого, иконки редактора) srcset 1x/2x генерится автоматически.
